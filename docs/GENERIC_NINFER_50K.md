# Generic Nomos data line

This is the active training-data plan for Nomos. It is independent of
Fitz-Sage vocabulary and does not import a Fitz-Sage implementation.

## What is generated

Each row combines three separately controlled parts:

1. `configs/matrix.generic.v3.json` supplies a unique multidimensional state.
2. `fitz_tool/generic_pilot_v3.py` materializes an opaque tool registry, legal
   candidate set, deterministic labels and hard negatives.
3. `tools/generate_generic_ninfer_v3.py` asks local NInfer/Qwen for the user
   request and a difficult paraphrase.

NInfer therefore supplies the language surface for every accepted row. It does
not decide the label by naming a tool: labels are accepted only when the
deterministic matrix oracle and registry contract agree. This prevents teacher
wording errors from becoming ground truth.

The generator rejects project markers (`fitz`, `sage`, `bm25`), concrete tool
IDs, registry IDs and mismatched assignment IDs. It flushes each accepted row
to JSONL and can resume after interruption. A damaged or duplicated resume file
is repaired into a unique-row file with a local backup.

NInfer/Qwen is the primary local teacher. DeepSeek can continue an interrupted
corpus when faster API generation is needed; each row records its actual
teacher, model and prompt version, and mixed-teacher corpora remain auditable.

## Cohorts

| Cohort | Rows | Purpose |
| --- | ---: | --- |
| `train` | 34,000 | Main training distribution |
| `validation` | 4,000 | Development checkpoint |
| `familiar_registries` | 2,500 | New registry fingerprints with familiar families |
| `unseen_tool_ids` | 2,000 | Opaque ID changes |
| `id_renames` | 1,000 | Renamed candidate identifiers |
| `schema_variants` | 1,000 | Equivalent capability with schema variation |
| `modality_variants` | 1,000 | Modality constraints and substitutions |
| `heldout_family` | 2,000 | Entire tool-family holdout |
| `heldout_sources` | 1,000 | Source-card holdout |
| `heldout_questions` | 1,000 | Disjoint question-template holdout |
| `alternate_registry` | 500 | Alternate registry composition |
| **Total** | **50,000** | |

The generator samples a new matrix cell for every row and records
`matrix_cell_id`, `type_signature` and `instance_signature`. These are checked
for uniqueness before training. Holdout registries, families, sources and
question templates are checked for overlap with training.

## Completed 50k run

The current corpus contains 50,000 validated rows: 1,728 generated by local
NInfer/Qwen3.8-27B and 48,272 generated by DeepSeek-v4-flash. Generation used
four rows per request and 128 concurrent requests. The full validator reports
50,000 unique matrix cells, type signatures, instance signatures and question
strings, with no train/holdout leakage. A 100-row reservoir audit found no
JSON, schema, genericity or provenance errors.

The full 34,000-row training checkpoint reaches 87.4% Recall@1, 96.9%
Recall@3 and 0.923 MRR over all 50,000 rows, with a zero illegal-candidate
rate. On holdouts, Recall@1 is 84.7% for the held-out tool family, 86.3% for
unseen tool IDs, 81.0% for held-out question templates and 88.3% for held-out
sources. Registry/order/ID invariance checks pass.

The external-registry suite uses 1,000 held-out questions against four
hand-authored registry styles with new IDs, families, descriptions, schemas and
modalities. The frozen 50k checkpoint reaches 57.2%/83.5% mean Recall@1/Recall@3
(`spectrum` 65.6%/85.5%, `quarry` 54.9%/79.4%, `weave` 53.5%/84.7%, `relay`
54.9%/84.5%). The shuffled candidate-order baseline is 14.2%/41.5%, and the
illegal-candidate rate is 0% for every registry. This proves useful transfer,
but identified a portability gap in `compare_evidence`, `search_content`,
`search_metadata` and `exact_pattern_search`.

## Portability expansion results

The first 20k-row augmentation was deliberately concentrated on those weak
capabilities. Training on all 20k new rows plus the 50k base (the 70k line)
over-corrected: external mean Recall@1/Recall@3 fell to 42.9%/76.5%, and the
internal test Recall@1 fell to 71.2%. That checkpoint is rejected.

A controlled 55k mix—50k base rows plus 5k selected augmentation rows—kept the
internal score near the original and raised external mean Recall@1/Recall@3 to
59.5%/84.0%. This established the data-mixture gate for a broader expansion.

The accepted 100k corpus is not 100k fresh rows. It is 50k original generic
rows, 20k targeted portability rows and 30k balanced portability rows. The
corpus validates with 100,000 unique matrix cells, type signatures, instance
signatures and questions; zero invalid rows; zero teacher errors; and no
held-out leakage. The checkpoint trains on a balanced 54,000-row subset of the
84,000 train-partition rows. Its internal checkpoint metrics are 85.5%/96.0%
Recall@1/Recall@3 with zero invalid candidates.

On the frozen external suite, the 100k checkpoint reaches:

| Registry | Recall@1 | Recall@3 |
| --- | ---: | ---: |
| `spectrum` | 72.2% | 88.8% |
| `quarry` | 67.5% | 86.7% |
| `weave` | 66.7% | 88.0% |
| `relay` | 67.5% | 88.7% |
| **Mean** | **68.5%** | **88.0%** |

This is the current accepted line. The next step is not another blind data
increase: measure the repaired live external-agent loop on a stratified sample
and extract only deterministically accepted decision states before collecting
more training data.

## Execution-loop gate

The development-only runner harness now sends `runner-request.v2` objects
through a separate router process and advances a deterministic capability
simulator after each correct selection. It evaluated 200 held-out questions
against each of the four unseen registries: 800 tasks and 2,760 planned
decisions in total. The simulator is not a real API runner, so this is a state
transition gate rather than production evidence.

The no-router candidate-order baseline completed 0.88% of tasks. The 50k model
completed 12.38%, and the 100k model completed 12.25%; all three had a 0%
illegal-selection rate. The 100k model was better on the first decision (62.4%
versus 53.9% for 50k), but it lost more often after the first successful tool
result. The 100k model is therefore still a research candidate, not yet a
promoted runtime model.

The first real-agent smoke used the external Fitz-Sage V2 runner boundary on
two fixture scenarios. Both were rejected because V2 repeated incomplete or
non-visible tool calls and reached its step limit. The V2-specific
`tools.nomos_openai_proxy` bridge now translates the observable request, ranks
only supplied legal candidates, preserves source-modality constraints, and
repairs bounded output-format failures. On the aligned payments fixture, the
repaired path produced 10 decisions, selected the expected evidence and passed
deterministic acceptance. This is an integration proof, not a broad quality
score; the next gate is a stratified external-runner sample and clean
accepted-state extraction.

## Commands

Smoke test the live teacher:

```text
python -m tools.generate_generic_ninfer_v3 --count 8 --seed 20260824 --model Qwen/Qwen3.8-27B --no-api-key --batch-size 4 --concurrency 2 --output data/generated/ninfer_generic_smoke.jsonl --manifest runs/ninfer_generic_smoke_manifest.json
```

Generate or resume the full corpus:

```text
python -m tools.generate_generic_ninfer_v3 --count 50000 --seed 20260824 --model Qwen/Qwen3.8-27B --no-api-key --batch-size 8 --concurrency 4 --retries 8 --invalid-retries 3 --timeout 180 --max-tokens 2500 --output data/generated/nomos_generic_ninfer_50000.jsonl --manifest runs/nomos_generic_ninfer_50000_manifest.json --resume
```

Continue the same file with DeepSeek (keep the API key in the process
environment only). DeepSeek's [documented per-account concurrency limit](https://api-docs.deepseek.com/quick_start/rate_limit/)
is 2,500; this run uses 128 concurrent requests and four rows per request:

```text
$env:FITZ_TOOL_DEEPSEEK_API_KEY = '<temporary-key>'
python -m tools.generate_generic_ninfer_v3 --teacher deepseek --model deepseek-v4-flash --base-url https://api.deepseek.com/v1 --count 50000 --seed 20260824 --batch-size 4 --concurrency 128 --retries 3 --invalid-retries 2 --timeout 120 --max-tokens 2000 --output data/generated/nomos_generic_ninfer_50000.jsonl --manifest runs/nomos_generic_ninfer_50000_manifest.json --resume
```

If the teacher repeats wording, repair only the repeated questions while
preserving their matrix assignments:

```text
python -m tools.repair_generic_question_duplicates --input data/generated/nomos_generic_ninfer_50000.jsonl --base-url https://api.deepseek.com/v1 --model deepseek-v4-flash --batch-size 4 --concurrency 128 --retries 3 --invalid-retries 2 --timeout 120 --max-tokens 2000 --max-attempts 6 --seed 20260824
```

Validate the complete corpus:

```text
python -m tools.validate_generic_router_v3 --input data/generated/nomos_generic_ninfer_50000.jsonl --manifest runs/nomos_generic_ninfer_50000_manifest.json --require-external-teacher --report runs/nomos_generic_ninfer_50000_validation.json
python -m tools.audit_generic_ninfer_sample --input data/generated/nomos_generic_ninfer_50000.jsonl --sample-size 100 --seed 20260824 --output runs/nomos_generic_ninfer_50000_sample_audit.json
python -m tools.test_external_registry --artifact artifacts/nomos_generic_ninfer_full.pt --input data/generated/nomos_generic_ninfer_50000.jsonl --output runs/nomos_generic_external_registry_test.json --limit 1000 --seed 20260824
```

Generate the separate, targeted portability augmentation after a fresh teacher
credential is available. It preserves the 50k file and creates 20k new,
matrix-unique training rows; the local NInfer command is shown here, while the
same tool accepts `--teacher deepseek` for an API-backed run:

```text
python -m tools.generate_portability_augmentation --base-input data/generated/nomos_generic_ninfer_50000.jsonl --count 20000 --start-index 50000 --seed 20260824 --batch-size 4 --concurrency 4 --no-api-key --output data/generated/nomos_generic_portability_augmentation_20000.jsonl --manifest runs/nomos_generic_portability_augmentation_20000_manifest.json
```

The targeted augmentation remains useful for controlled mixtures. For the final
balanced expansion, use `--distribution balanced` and reserve new matrix cells
after the existing 70k line:

```text
python -m tools.generate_portability_augmentation --base-input data/generated/nomos_generic_portability_70000.jsonl --count 30000 --start-index 70000 --seed 20260825 --distribution balanced --teacher deepseek --model deepseek-v4-flash --base-url https://api.deepseek.com/v1 --batch-size 4 --concurrency 128 --output data/generated/nomos_generic_portability_augmentation_balanced_30000.jsonl --manifest runs/nomos_generic_portability_augmentation_balanced_30000_manifest.json
python -m tools.validate_generic_router_v3 --input data/generated/nomos_generic_portability_augmentation_balanced_30000.jsonl --manifest runs/nomos_generic_portability_augmentation_balanced_30000_manifest.json --expected-count 30000 --require-external-teacher --allow-custom-cohorts --report runs/nomos_generic_portability_augmentation_balanced_30000_validation.json
```

Merge and validate the 100k corpus before training:

```text
python -m tools.merge_generic_corpora --input data/generated/nomos_generic_portability_70000.jsonl --input data/generated/nomos_generic_portability_augmentation_balanced_30000.jsonl --output data/generated/nomos_generic_portability_100000.jsonl --manifest runs/nomos_generic_portability_100000_manifest.json
python -m tools.validate_generic_router_v3 --input data/generated/nomos_generic_portability_100000.jsonl --manifest runs/nomos_generic_portability_100000_manifest.json --expected-count 100000 --require-external-teacher --allow-custom-cohorts --report runs/nomos_generic_portability_100000_validation.json
python -m tools.train_encoder_v2 --input data/generated/nomos_generic_portability_100000.jsonl --output artifacts/nomos_generic_portability_100000.pt --train-count 54000 --epochs 12 --feature-dim 512 --hidden-dim 128 --learning-rate 0.002 --seed 20260824 --batch-size 4096
python -m tools.test_external_registry --artifact artifacts/nomos_generic_portability_100000.pt --input data/generated/nomos_generic_portability_100000.jsonl --output runs/nomos_generic_portability_100000_external_registry.json --limit 1000 --seed 20260824
```

Train and evaluate only after validation passes:

```text
python -m tools.train_encoder_v2 --input data/generated/nomos_generic_ninfer_50000.jsonl --output artifacts/nomos_generic_ninfer_50000.pt --train-count 34000 --epochs 12 --feature-dim 512 --hidden-dim 128 --learning-rate 0.002 --seed 20260824 --batch-size 4096
python -m tools.evaluate_router_v2 --artifact artifacts/nomos_generic_ninfer_50000.pt --input data/generated/nomos_generic_ninfer_50000.jsonl --output runs/nomos_generic_ninfer_50000_evaluation.json
```

The evaluation must report performance by cohort, target capability and tool
family, plus candidate-order, identifier, schema, modality and question
ablations. A high overall score is not sufficient if the unseen-family or
unseen-registry gates fail.

## Boundary with Fitz-Sage

`fitz_tool/adapters/fitz_sage_v2.py` remains an integration adapter for testing
an external runner. Its registry is not part of this 50k corpus. The generic
router and generator must remain importable without a Fitz-Sage checkout.
